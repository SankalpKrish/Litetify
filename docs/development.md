# Development

This guide covers everything you need to contribute to Litetify, from setting up
a development environment to understanding the CI/CD pipeline.

---

## 1. Development Environment Setup

### Prerequisites

| Dependency | Minimum Version | Install                                                                                                         |
| ---------- | --------------- | --------------------------------------------------------------------------------------------------------------- |
| Bun        | >= 1.3          | `powershell -c "irm bun.sh/install.ps1 \| iex"` or [bun.sh/docs/installation](https://bun.sh/docs/installation) |
| Rust       | stable (1.77.2) | [rustup.rs](https://rustup.rs)                                                                                  |
| Node.js    | >= 20           | Used by some tooling; Bun is the primary package manager                                                        |

### Platform-Specific Dependencies

**Windows:** WebView2 ships with Windows 11. On Windows 10 it is available via
runtime; the Tauri installer prompts if missing.

**Linux:**

```bash
sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev \
  librsvg2-dev patchelf libxdo-dev gnome-keyring dbus-x11
```

**macOS:** Xcode Command Line Tools (`xcode-select --install`).

### Clone and Install

```bash
git clone https://github.com/SankalpKrish/Litetify.git
cd Litetify
bun install
```

### Verifying the Setup

```bash
bun run lint          # ESLint (zero-warnings)
bun run typecheck     # TypeScript type checking
bun run test          # Vitest frontend tests
cargo test --manifest-path src-tauri/Cargo.toml   # Rust tests
```

## 3. Frontend Development Workflow

### Vite Dev Server

Start the web-only dev server for UI work without the Rust shell:

```bash
bun run dev
```

This starts Vite on `http://localhost:1420`. The port is fixed (`strictPort:
true`) because Tauri's webview expects exactly this URL.

### Full Desktop App (Tauri + HMR)

```bash
bun run tauri dev
```

This launches both the Vite dev server and the Tauri desktop window. The
webview loads from `http://localhost:1420`. HMR WebSocket runs on port 1421
when `TAURI_DEV_HOST` is set (e.g. for remote device testing).

Key Vite settings (from `vite.config.ts`):

| Setting           | Value             | Purpose                                        |
| ----------------- | ----------------- | ---------------------------------------------- |
| `server.port`     | 1420              | Fixed port for Tauri webview                   |
| `server.hmr.port` | 1421              | HMR WebSocket port (when `TAURI_DEV_HOST` set) |
| `clearScreen`     | `false`           | Prevents Vite from hiding Rust compiler errors |
| `watch.ignored`   | `**/src-tauri/**` | Cargo handles Rust rebuilds                    |

### CSS Modules Pattern

Litetify uses **CSS Modules** for component-scoped styling, paired with a
shared design token system.

```css
/* PlayerView.module.css */
.root {
  display: flex;
  flex-direction: column;
  gap: var(--space-md);
}

.title {
  font: var(--font-heading);
  color: var(--color-text-primary);
}
```

```tsx
import styles from './PlayerView.module.css';

export function PlayerView() {
  return (
    <div className={styles.root}>
      <h2 className={styles.title}>Now Playing</h2>
    </div>
  );
}
```

**Design tokens** live in `src/styles/tokens.css` and define over 72 CSS
custom properties covering color, typography, spacing, and elevation. Themes
override these tokens to change the entire appearance.

```css
/* Consumer - use tokens everywhere */
color: var(--color-text-primary);
background: var(--color-surface);
font: var(--font-body);
```

### State Management

| Concern           | Solution                  | Location                                        |
| ----------------- | ------------------------- | ----------------------------------------------- |
| Server data       | `@tanstack/react-query`   | `src/lib/queries/`                              |
| Client state      | Zustand stores            | `src/features/*/*Store.ts`                      |
| Persistent config | Tauri store plugin (Rust) | `src/lib/config.ts` + `src-tauri/src/config.rs` |
| View routing      | Zustand (no URL router)   | `src/lib/ViewState.tsx`                         |

### Key Modules

- **`src/lib/api.ts`** - Typed wrapper around `@tauri-apps/api/core`'s
  `invoke()`. Every Tauri command is called through this module.
- **`src/lib/queries/`** - Per-resource React Query hooks with retry, caching,
  and stale-time configuration.
- **`src/features/auth/authStore.ts`** - Zustand store managing auth state,
  token lifecycle, and Spotify Client ID.
- **`src/features/player/playerStore.ts`** - Zustand store for playback
  state, volume, shuffle, and repeat.

## 4. Rust Development Workflow

### Architecture Overview

The Rust backend runs in Tauri's privileged process and handles:

- **Auth** - PKCE OAuth flow, callback server, OS keychain token storage
- **API proxy** - All Spotify Web API calls go through Rust-side `#[tauri::command]` functions, not the browser
- **Playback** - WebSDK engine commands relayed to the frontend via Tauri events
- **Mod filesystem** - Safe file reads for mod manifests and entry files

### Cargo Features

```toml
[features]
default = []
```

**v1.0.0 build** - Web Playback SDK engine only, the app controls Spotify
playback through the Spotify Web API (play, pause, seek, etc.) via the
browser's Web SDK. There is no `librespot` Cargo feature in this release.

### Tauri Commands

All Rust-to-frontend IPC is defined in `src-tauri/src/lib.rs` via the
`#[tauri::command]` attribute and registered in `generate_handler![]`.

**Pattern for adding a new command:**

1. Define the function in the appropriate module:
   ```rust
   #[tauri::command]
   pub async fn my_new_command(app: AppHandle, arg: String) -> Result<String, String> {
       // ...
   }
   ```
2. Register it in `lib.rs`:
   ```rust
   .invoke_handler(tauri::generate_handler![
       // ... existing commands ...
       my_module::my_new_command,
   ])
   ```
3. Call from the frontend:
   ```typescript
   import { invoke } from '@tauri-apps/api/core';
   const result = await invoke<string>('my_new_command', { arg: 'value' });
   ```

Command categories:

| Module      | Commands                                                                         | Purpose           |
| ----------- | -------------------------------------------------------------------------------- | ----------------- |
| `auth/`     | `login`, `logout`, `check_auth`, `get_valid_token`, `get_profile`                | OAuth lifecycle   |
| `api/`      | `api_get_me`, `api_search`, `api_play`, `api_pause`, ...                         | Spotify API proxy |
| `playback/` | `engine_play`, `engine_seek`, `engine_pause`, `engine_resume`, ... (websdk only) | Playback control  |
| `mods/`     | `scan_mods`, `read_mod_file`, `get_mods_path`, `open_mods_folder`, `open_path`   | Mod filesystem    |

### The PlaybackEngine Trait

Defined in `src-tauri/src/playback/mod.rs`, this trait abstracts the
WebSDK engine:

```rust
pub trait PlaybackEngine: Send + Sync {
    fn play(&self, uri: Option<&str>) -> Result<(), String>;
    fn pause(&self) -> Result<(), String>;
    fn resume(&self) -> Result<(), String>;
    fn seek(&self, position_ms: u64) -> Result<(), String>;
    fn set_volume(&self, volume: u8) -> Result<(), String>;
    fn next(&self) -> Result<(), String>;
    fn previous(&self) -> Result<(), String>;
    fn toggle_shuffle(&self) -> Result<(), String>;
    fn cycle_repeat(&self) -> Result<(), String>;
}
```

### Typeshare

Types annotated with `#[typeshare]` in Rust are automatically mirrored as
TypeScript interfaces in `src/lib/types.generated.ts`. See section 7 for
details.

### Rust Formatting and Linting

```bash
# Format
cargo fmt --manifest-path src-tauri/Cargo.toml

# Lint
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings

# Test
cargo test --manifest-path src-tauri/Cargo.toml
```


`typescript-eslint`:


- Covers `**/*.{ts,tsx}`, ignores `dist`, `node_modules`, `src-tauri/target`,
  `coverage`

### Prettier

```bash
bun run format             # Write formatted files

```

Settings (`.prettierrc`): `semi: true`, `singleQuote: true`,
`trailingComma: "all"`, `printWidth: 80`, `tabWidth: 2`.

```bash
bun run typecheck          # tsc --noEmit
```

Key compiler settings (`tsconfig.json`):

- `strict: true` - full strict mode
- `noUnusedLocals` / `noUnusedParameters` - errors on dead code

### Spell Checking

```bash
bun run spellcheck         # cspell --no-progress .
```

Configuration in `cspell.json` with ~180 project-specific terms
(litetify, librespot, tauri, zustand, catppuccin, crossfade, etc.).

Configuration in `knip.json`. Ignores mod entry points, test files, and

### Clippy (Rust)

Runs as part of the CI `lint` job.

| Job                 | Tool                           | Failure Behaviour                 |

## 7. Type Generation

Litetify uses **typeshare** to automatically generate TypeScript interfaces
from Rust structs, ensuring type safety across the IPC boundary.

### How It Works

1. Annotate Rust structs with `#[typeshare]` and `#[derive(Serialize,
Deserialize)]`:

   ```rust
   use typeshare::typeshare;

   #[typeshare]
   #[derive(Debug, Clone, Serialize, Deserialize)]
   pub struct PlaybackState {
       pub uri: Option<String>,
       pub is_playing: bool,
       // ...
   }
   ```

2. Run the generation command:

   ```bash
   bun run types:generate
   ```

   This invokes:

   ```bash
   typeshare src-tauri/src/ --lang=typescript --output-file=src/lib/types.generated.ts
   ```

3. The generated file (`src/lib/types.generated.ts`) produces TypeScript
   interfaces mirroring every `#[typeshare]` struct:

   ```typescript
   export interface PlaybackState {
     uri?: string;
     is_playing: boolean;
     // ...
   }
   ```

4. These are re-exported through `src/lib/types.ts`, which also adds
   hand-maintained types that have no Rust counterpart.

### Type Sources

| Source                  | File                         | Responsibility                                 |
| ----------------------- | ---------------------------- | ---------------------------------------------- |
| Rust `#[typeshare]`     | `src-tauri/src/*.rs`         | Spotify API types, mod types, playback types   |
| Generated output        | `src/lib/types.generated.ts` | Auto-generated, do not edit                    |
| Re-exports + hand types | `src/lib/types.ts`           | Public type surface, additional non-Rust types |

### CI Gate

The `types:check` script verifies generated types stay in sync:

```bash
bun run types:generate && git diff --exit-code src/lib/types.generated.ts
```

This runs in the `pre-release-gates` CI job. If a Rust struct changes and
types are not regenerated, the pipeline fails.

## 9. Mod Development

Litetify's mod system allows third-party customisation without rebuilding the
app. Mods are folders dropped into the `mods/` directory and enabled from the
settings panel.

### Mod Types

| Type           | What It Does                                        | Entry                    |
| -------------- | --------------------------------------------------- | ------------------------ |
| **Theme**      | CSS that overrides design tokens to change the look | `theme.css`              |
| **Extension**  | Sandboxed JavaScript in an isolated iframe          | `extension.js`           |
| **Custom App** | Full-page view that appears as a new sidebar tab    | `app.js` or `index.html` |

### Manifest Schema

Every mod must have a `manifest.json` at its root:

```json
{
  "name": "My Mod",
  "version": "1.0.0",
  "type": "theme",
  "entry": "theme.css",
  "description": "A brief description of the mod.",
  "author": "Your Name",
  "litetifyApiVersion": "1.0.0",
  "permissions": ["player", "storage"]
}
```

| Field                | Required        | Description                                         |
| -------------------- | --------------- | --------------------------------------------------- |
| `name`               | Yes             | Human-readable mod name                             |
| `version`            | Yes             | Semantic version string                             |
| `type`               | Yes             | One of `"theme"`, `"extension"`, `"app"`            |
| `entry`              | Yes             | Entry file path relative to the mod folder          |
| `description`        | No              | Short description displayed in the mods panel       |
| `author`             | No              | Author name                                         |
| `litetifyApiVersion` | Yes             | API version the mod targets                         |
| `permissions`        | Extensions only | `["player"]`, `["storage"]`, `["api:search"]`, etc. |
| `icon`               | No              | Icon file path relative to the mod folder           |

### Extension Development

Extensions run in a sandboxed iframe with no direct DOM access to the main
app. Communication happens exclusively through the `window.Litetify` API.

**`window.Litetify` API surface:**

```typescript
interface LitetifyAPI {
  // Player controls
  player: {
    play(uri?: string): Promise<void>;
    pause(): Promise<void>;
    seek(positionMs: number): Promise<void>;
    next(): Promise<void>;
    previous(): Promise<void>;
    setVolume(volume: number): Promise<void>;
    toggleShuffle(): Promise<void>;
    cycleRepeat(): Promise<void>;
  };

  // Storage (key-value, scoped to the mod)
  storage: {
    get(key: string): Promise<string | null>;
    set(key: string, value: string): Promise<void>;
    remove(key: string): Promise<void>;
  };

  // Event subscription
  on(event: string, callback: (data: unknown) => void): void;
  off(event: string, callback: (data: unknown) => void): void;

  // UI
  notifications: {
    show(message: string, type?: 'info' | 'error' | 'success'): void;
  };
}
```

Events that extensions can subscribe to:

| Event            | Payload                                                  | Description            |
| ---------------- | -------------------------------------------------------- | ---------------------- |
| `track-change`   | `{ uri, name, artist, album, album_image, duration_ms }` | Track changed          |
| `playback-state` | `{ is_playing, position_ms, volume }`                    | Playback state updated |
| `shuffle-change` | `boolean`                                                | Shuffle mode toggled   |
| `repeat-change`  | `"off" \| "context" \| "track"`                          | Repeat mode changed    |

**Example extension** (`mods/examples/skip-to-favorite/extension.js`):

```javascript
(function () {
  const { player, storage, on, notifications } = window.Litetify;

  let favoritePosition = null;

  // Listen for track changes
  on('track-change', (track) => {
    storage.get(`fav-${track.uri}`).then((pos) => {
      favoritePosition = pos ? parseInt(pos, 10) : null;
    });
  });

  // Expose a global function the user can call from the mods panel
  window.markFavorite = function () {
    player.seek(favoritePosition || 30000);
    notifications.show('Skipped to favorite section!');
  };
})();
```

### Internal Mod Architecture

The mod system spans both Rust and TypeScript:

| Layer            | Location              | Responsibility                                               |
| ---------------- | --------------------- | ------------------------------------------------------------ |
| Rust filesystem  | `src-tauri/src/mods/` | Scan `mods/` directory, validate manifests, read entry files |
| Frontend loader  | `src/mods/loader.ts`  | Init, scan, enable/disable, persist state                    |
| Frontend sandbox | `src/mods/sandbox.ts` | Create isolated iframes for extensions                       |
| Frontend themes  | `src/mods/themes.ts`  | Inject CSS into the document                                 |
| Frontend apps    | `src/mods/apps.tsx`   | Render custom app views in sidebar tabs                      |
| Frontend API     | `src/mods/api.ts`     | Build `window.Litetify` object for each extension            |
| Frontend store   | `src/mods/store.ts`   | Zustand store for enabled/disabled mod state                 |

### Continuous Integration (CI)

**File:** `.github/workflows/ci.yml`

Runs on every push or pull request to `main`. Cancels in-progress runs for

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

**Jobs (executed in dependency order for `build`):**

| Job                 | Tool                        | Dependencies                  | Description                       |

| `lint`              | Clippy (Rust) + ESLint      | -                             | Rust lints + frontend lint        |

| `typecheck`         | `tsc --noEmit`              | -                             | TypeScript type safety            |
| `test`              | Vitest + Cargo test         | -                             | Frontend + Rust tests             |
| `build`             | `bun run build`             | lint, format, typecheck, test | Full frontend build               |

| `security-audit`    | `cargo audit`               | -                             | Vulnerability scanning            |

## Development Tips

### Port Conflicts

If port 1420 is in use, Vite's `strictPort: true` causes an immediate error.
Kill the stale process:

```bash
# Windows
netstat -ano | findstr :1420
taskkill /PID <PID> /F

# Linux/macOS
lsof -ti:1420 | xargs kill -9
```

### Quick Frontend Iteration

For UI-only work without the Rust backend, use `bun run dev` and open
`http://localhost:1420` in a browser. Most features that depend on Tauri IPC
will not work, but component development and styling can proceed without
Cargo compilation.

### Adding a New Spotify API Endpoint

1. Add the Rust command in `src-tauri/src/api/` (or an existing resource file)
2. Register it in `lib.rs` `generate_handler![]`
3. Add a typed wrapper in `src/lib/api.ts`
4. If the response shape is new, add a `#[typeshare]` struct in Rust and run
   `bun run types:generate`
5. Add a React Query hook in `src/lib/queries/`

### Debug Logging

Rust errors propagate to the frontend through `Result<T, String>` returns
from `#[tauri::command]`. Use `eprintln!` or `tracing` macros during
development. The Tauri webview console (opened via right-click → Inspect)
shows frontend errors.
